Executive summary

Yes — unified evaluation

.timeline assets and EvaluateTimeline() sample all track types in one call: animation clips, audio keys, transform/property curves, method/event keys.

Yes — runtime apply (TimelinePlaybackSystem)

TimelinePlaybackSystem runs each frame for Animator entities with source == Timeline: evaluates the timeline and applies clips, transforms, audio keys, and registered method callbacks. See TimelinePlaybackSystem.

PlayTimeline sets timelineGuid, source = Timeline, and pendingCommand = Play. Runtime consumption of that command is not a full director — see gap below.

Evaluation vs application

Apply layer (shipped)

EvaluateTimeline computes samples and events. TimelinePlaybackSystem + ApplyTimelineEvaluation in Engine/Rendering/TimelinePlayback.cpp push them into ECS, AnimatorRef, AudioSystem, and the method callback registry.

Per-frame apply entry point:

ApplyTimelineEvaluation(evaluation, context);
// context: world, root entity, subtree, assetManager, optional audioSystem

Editor enter-play still calls ApplyTimelineEvaluation once for an initial pose, then the ECS system owns playback.

TimelinePlaybackSystem shipped

TimelinePlaybackSystem runs each frame on entities with Animator.source == Timeline, advances TimelinePlaybackState, calls EvaluateTimeline(previousTime, currentTime), and applies all result channels — Unity PlayableDirector style.

Responsibility

Evaluate (already exists) answers “what happened between t₀ and t₁?”
TimelinePlaybackSystem answers “push that into the scene graph and subsystems.”

Per-frame loop (sketch)

1 · QueryEntities with Animator where source == Timeline, timeline playing, and valid timelineGuid.
2 · AdvanceUpdate local playback clock (deltaTime * speedScale, loop wrap via GetTimelineDuration).
3 · EvaluateEvaluateTimeline(timeline, prevT, currT, { .Loop = animator.loop })
4 · ApplyDispatch result vectors to transforms, AnimatorRef, audio, callbacks (below).

Runtime component: TimelinePlaybackState

Header: Engine/Include/Components/Animation/TimelinePlaybackState.h

struct TimelinePlaybackState
{
    float32 timeSeconds = 0.0f;
    float32 previousTimeSeconds = 0.0f;
    bool playing = false;
    bool paused = false;
};

Added automatically on the Animator root when timeline playback starts. Animator remains the authoring surface (PlayTimeline, Pause, Seek); pendingCommand is consumed by the system each frame.

Binding: TargetPath → entity

  • Resolve track.TargetPath against the animated root subtree (same hierarchy walk as CollectEntitiesInSubtree in play mode).
  • Cache path → EntityHandle when timeline asset or hierarchy changes (invalidate on reparent).
  • Missing binding: log once, skip track (do not crash evaluation).

Method / code events

TimelineMethodEvent carries MethodName, Arguments, and TypedArguments. Phase 1: engine-native callback registry (string name → std::function) for tests and editor. Phase 2: route through existing Animator callback process (Idle / Physics / Manual) and scripting ABI.

What this system should not own

  • JSON load/save — stays in AnimationTimeline.cpp / TimelineAsset
  • Editor scrub UI — AnimationWindowPanel / TimelineState
  • Skeletal pose solve — still AnimationSystem + SkinningUploadSystem after AnimatorRef is set
  • Editor-only one-shot resolve — ResolveTimelinePlayback can delegate to shared helper or shrink once system ships

Remaining limitations

  • Multi-clip skeletal blend uses dominant weight only.
  • Video tracks are editor-only (editorOnly.videoTracks).
  • Path → entity cache not implemented (resolve each frame).
